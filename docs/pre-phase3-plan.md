## 差距结论（对比评审摘要）

核心流程（探索 → 固化 → 回放 → 自愈）不输市面 MCP 工具，且自愈是显式可审计的差异化优势。
差距集中在「失败诊断」与「规模化体验」两块：

- **失败现场不可回看**：run-record 只留在对话里，不落盘；市面标杆（Playwright Trace Viewer）每一步都有 DOM 快照与截图
- **验证维度单一**：只有语义断言，无视觉回归；样式改版完全不可见
- **CI 可信度缺口**：无失败重试，一次抖动即误报；每条 trace 都从头登录，耗时且脆
- **规模化组织缺失**：用例无元数据、无历史趋势、报告只有文本

## 执行顺序

### 第一批：CI 诊断与可信度（A + B + C，预估 2~3 天）

- **A 是地基**：F 依赖 run 落盘；B 的重试记录要落盘才可审计；也是 heal 转人工的交接材料
- **B 小时级**：套件层对单条 trace 自动重试 1 次，带 `retryOf` 标记——fail-fast 语义保留在单条内部，不冲突
- **C 决定 suite 耗时结构**：用例集规模化后登录是耗时大头；与 Context 隔离可调和（显式注入 ≠ 隐式共享）

### 第二批：验证维度扩展（D）

截图断言作为 assert 新类型（`screenshot-match`），基线入 git；复用 A 的现场归档基建。
单独一批因为它需要精细设计：基线阈值、稳定性等待后截图、diff 报告形态。

### 第三批：规模化组织（E + F + G）

- E：suite 从显式列路径升级为按标签/目录选择
- F：依赖 A；回答「这条用例最近挂了几次、是不是 flaky」
- G：vars 从单组值升级为数据集迭代

### 第四批：按需增强（H + I，看实际需求触发）

H 在外部依赖不稳定首次实际咬人时做；I 在演示/复盘场景有真实观众时做。

## 非目标（避免日后反复纠结）

多浏览器（CDP 绑死 Chrome，跨浏览器等于重做感知层）、云端浏览器（内部系统定位）、
手动录制（agent 探索是更优路线）、silent auto-heal（显式自愈是安全优势）、
人类化操作节奏（设计文档既定非目标）。
